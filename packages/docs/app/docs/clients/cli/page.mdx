# <Brand /> CLI

The CLI is the direct command-line client and the runtime service host used by editor clients.

## Install

```sh
npm install -g @truss-harness/cli
```

See the [CLI package on npm](https://www.npmjs.com/package/@truss-harness/cli) for the latest published version and package details.

The global installer prints the first commands to run. `truss-cli` and `truss-cli help` display the complete built-in reference without requiring a model.

## Commands

| Command | Purpose |
| --- | --- |
| <CliCommand /> `chat [prompt]` | Stream one task, or open persistent chat with no prompt |
| <CliCommand /> `models` | List detected local endpoints and models |
| <CliCommand /> `setup` | Interactively discover and save local-model defaults |
| <CliCommand /> `config path` | Print user and workspace configuration paths |
| <CliCommand /> `config init` | Create a workspace profile template |
| <CliCommand /> `config trust` | Authorize the exact reviewed workspace config |
| <CliCommand /> `config status` | Show effective policy and trust provenance |
| <CliCommand /> `agents trust <id>` | Authorize one reviewed migrated/manual profile |
| <CliCommand /> `init` | Generate or refresh repository instructions |
| <CliCommand /> `update [note]` | Store Git state and a handoff note |
| <CliCommand /> `status` | Inspect durable workspace state |
| <CliCommand /> `clear-memory` | Reset durable workspace memory |
| <CliCommand /> `commands` | Print shared slash commands |
| <CliCommand /> `serve` | Host the JSONL runtime protocol |
| <CliCommand /> `agents list` | List workspace-local managed-agent profiles |
| <CliCommand /> `agents add <name>` | Create a profile from the selected configuration |
| <CliCommand /> `agents run <id> <task>` | Run a managed profile and stream its status |
| <CliCommand /> `agents remove <id>` | Remove an idle profile |

## Managed agents

Use `agents add` to create a focused workspace-local profile from the current
configuration, then pass its ID to `agents run`. Profiles can use different
providers, models, modes, and approval policies; credentials remain in the
host configuration rather than the profile file. The CLI keeps the newest 50
terminal summaries in `.truss-harness/agents/runs.json` for other control
surfaces to inspect after restart. See [Managed Agents](/docs/runtime/managed-agents)
for concurrency and Edit-run safety rules.

## Workspace commands

Run <CliCommand /> `init` to create or refresh generated repository context in `AGENTS.md`. Use <CliCommand /> `update [note]` to record Git state and a handoff note in durable memory, <CliCommand /> `status` to inspect it, and <CliCommand /> `clear-memory` to reset it. These commands do not need a configured model. <CliCommand /> `commands` prints the same slash-command help used by the TUI and VS Code panel.

## Chat

`chat` with a prompt creates an in-memory one-shot session, streams output to standard output, and prints tool requests to standard error. Run `truss-cli chat` without a prompt to keep one conversation open in the terminal.

```sh
truss-cli chat --profile ollama-coder --mode plan "Find the files that define the agent loop"
```

Direct CLI chat honors `--permission ask|auto-read|auto-all`. Ask is the default. Interactive approval uses the same terminal input as chat; Ctrl+C cancels a pending approval or run. Without a TTY, any tool needing approval fails promptly with instructions. Authorized automation can explicitly select `--permission auto-all`.

Review workspace configuration and run `truss-cli config trust` before using its authority-bearing settings. `truss-cli config status` shows the effective policy and provenance. Existing or manually edited managed-agent profiles require `truss-cli agents trust <id>` after review; locally created profiles receive individual receipts, and subsequent manual edits invalidate them.

Persistent chat retains conversation history and the starting configuration until you exit. Use `:mode chat`, `:mode plan`, or `:mode edit` to switch modes, or prefix a message with `--mode edit` to switch and send it at once. Use `:clear` for a fresh conversation, `:help` for controls, and `:exit` to close the session.

Add `--internet-access` to expose `web_search` and `web_fetch` for that run. Web tool calls still follow the selected approval policy. Use `--no-internet-access` to override an enabled profile.

When a Plan-mode run produces a checklist, the CLI prints the saved plan to standard error. The active plan is stored at `.truss-harness/plans/active.json` and is automatically included in later Edit-mode context.

## Service mode

```sh
truss-cli serve --profile ollama-coder
```

Service mode uses newline-delimited JSON on standard input/output. Output is reserved for protocol messages; do not add logs to standard output. The VS Code extension starts this service automatically.

## Model discovery

```sh
truss-cli models
```

This prints detected endpoints and model IDs for local servers.

## MCP servers

The CLI reads `mcpServers` from the shared configuration system and reports each connection before an Agent run. Run <CliCommand /> `config path` to locate the user and workspace files. Repository-provided MCP commands require content-bound local `config trust` authorization. See [MCP Servers](/docs/runtime/mcp) for the complete schema and safety behavior.
