# Get Started

## Requirements

- Node.js 22.15.1 or newer (Node 24 LTS recommended)
- npm 10 or newer
- A local model server such as Ollama, LM Studio, or llama.cpp
- Or an API key for a supported BYOK cloud provider
- Git for commit-message generation

## Install

```sh
npm install -g @truss-harness/truss
```

This installs both the CLI and the full-screen terminal workspace. Run `truss` for chat or `truss tui` for the terminal UI.

Confirm the executables are on your path:

```sh
truss help
truss tui --help
```

Running `truss` in an interactive terminal opens chat and starts guided setup if no model is configured. In scripts, a bare `truss` prints help.

### Install truss.nvim

Neovim users run the same local CLI service. The plugin defaults to `truss-cli`; either install the standalone `@truss-harness/cli` package as well, or set `command = "truss"` when using the bundled installation. Add the generated plugin distribution with lazy.nvim:

```lua
{
  "truss-agent/truss-harness",
  branch = "neovim-release",
  name = "truss.nvim",
  config = function()
    require("truss").setup({ command = "truss" })
    require("truss.lazy").setup()
  end,
}
```

Run `:checkhealth truss` after installation, then
`:TrussTestConnection` to intentionally test the selected provider. See the
[complete Neovim guide](/docs/clients/neovim) for profiles, commands, mappings,
context rules, and version compatibility.

## Interactive setup

```sh
truss setup
```

This detects local servers, lets you choose a model, and saves a reusable user-level default profile. The wizard is a command instead of an install-time prompt so npm installs remain safe in CI and scripts.

## Find a local model

```sh
truss models
```

When no model has been configured, <Brand /> probes standard local endpoints and selects a usable model automatically. An actively running Ollama model has priority.

## Run a first chat

```sh
truss chat "Explain this workspace."
```

If no local server is running, configure a profile first. See [Configuration](/docs/configuration).

For a cloud model, set `TRUSS_HARNESS_PROVIDER`, `TRUSS_HARNESS_MODEL`, and the matching provider key environment variable before running `truss chat`. See [Configuration](/docs/configuration#bring-your-own-key-byok).

## Run a first agent task

Run Agent/Edit mode only inside a workspace you trust. Direct CLI chat honors approval policy. Ask is the default, and a tool needing approval fails closed without a TTY. Use `--permission auto-all` only for explicitly authorized automation.

```sh
truss chat --mode edit "Read README.md and add one concise sentence describing the CLI. Make no other changes."
```

Use Neovim, the TUI, desktop app, or VS Code extension when you want interactive approval prompts and persistent conversation controls.

## Continue setup

Create a reusable local-model profile with <CliUsage command="config init" />, continue to [Local Models](/docs/local-models), or see [Troubleshooting](/docs/troubleshooting) when discovery or tool calling fails.

The bundled `@truss-harness/truss` package installs both clients. The standalone `@truss-harness/cli` (`truss-cli`) and `@truss-harness/tui` (`truss-tui`) packages remain supported.
